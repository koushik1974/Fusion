2. BACKEND URLs (Django REST API)
================================================================================

ANNOUNCEMENTS:
/api/announcements/                          - POST: Create announcement
/api/ann-data/<branch>/                      - GET: Fetch announcements by branch
/api/announcements/<announcement_id>/        - DELETE: Remove announcement

STOCK MANAGEMENT:
/api/stock/requests/                         - GET/POST: Stock requests list/create
/api/stock/requests/<stock_id>/decision/     - POST: Approve/Reject stock
/api/stock/requests/<stock_id>/issue/        - POST: Issue stock after approval

FEEDBACK:
/api/feedback/                               - GET/POST: Feedback list/submit
/api/feedback/<feedback_id>/resolve/         - POST: Resolve feedback

TIMETABLE:
/api/timetable/                              - GET/POST: Timetable list/create
/api/timetable/<timetable_id>/               - GET/PUT: Fetch/update timetable entry

FACILITIES:
/api/facilities/                             - GET/POST: Facilities list/create
/api/facilities/delete/                      - POST: Delete facilities
/api/labs/                                   - GET: All labs

DIRECTORY:
/api/faculty-directory/<branch>/             - GET: Faculty directory
/api/student-directory/<branch>/             - GET: Student directory
/api/alumni-directory/<branch>/              - GET: Alumni directory

PROFILE:
/api/student-profile/<roll_no>/              - GET: Student profile
/api/faculty-profile/<username>/             - GET: Faculty profile
/api/profile-change-requests/                - GET/POST: Profile changes list/submit
/api/profile-change-requests/<request_id>/decision/ - POST: Approve/reject profile change

7. AUTHENTICATION & PERMISSIONS
================================================================================

ALL ENDPOINTS REQUIRE:
- @api_view (GET, POST, PUT, DELETE as needed)
- @permission_classes([IsAuthenticated])
- @authentication_classes([TokenAuthentication])

ROLE-BASED ACCESS:
- ASSISTANT_PROFESSOR: Can request stock
- HOD: Can approve/reject stock, delete announcements, resolve feedback
- DEPTADMIN: Can issue/allocate stock
- STUDENT: Can submit feedback
- ALL_AUTHENTICATED: Can view directories, announcements

================================================================================
8. REQUEST/RESPONSE EXAMPLES
================================================================================

CREATE ANNOUNCEMENT:
POST /api/announcements/
{
  "programme": "B.Tech",
  "batch": "2021",
  "department": "CSE",
  "message": "Important announcement",
  "upload_announcement": <file>
}
Response: {id: 1, message: "Announcement created successfully."}

REQUEST STOCK:
POST /api/stock/requests/
{
  "brief": "Lab equipment",
  "request_details": "Need markers for class",
  "request_receiver": "CSE",
  "lab": "Computer Lab",
  "quantity": 10,
  "stock_item_name": "Marker"
}

APPROVE STOCK:
POST /api/stock/requests/<stock_id>/decision/
{
  "decision": "APPROVED"
}

SUBMIT FEEDBACK:
POST /api/feedback/
{
  "subject": "Lab issues",
  "description": "AC not working",
  "category": "CSE",
  "is_confidential": false
}

================================================================================
9. ERROR CODES & RESPONSES
================================================================================

400 BAD REQUEST: Missing required fields, invalid data
401 UNAUTHORIZED: Not authenticated
403 FORBIDDEN: Insufficient permissions
404 NOT FOUND: Resource doesn't exist
405 METHOD NOT ALLOWED: Directory endpoints are read-only
500 SERVER ERROR: Internal server error
